# راهنمای کلان فاز اول پروژه ویراستار هوشمند کتاب

## هدف سند

این سند چارچوب مشترک تیم برای طراحی و توسعه فاز اول محصول را مشخص می‌کند. هدف فاز اول ساخت محصول نهایی نیست؛ هدف، ارائه یک دموی پایدار و قابل ارائه است که مسیر اصلی محصول را نشان دهد.

## هدف فاز اول

در پایان فاز اول، کاربر باید بتواند:

1. وارد صفحه خانه محصول شود.
2. ارزش و کاربرد محصول را در چند ثانیه درک کند.
3. وارد محیط Editor شود.
4. یک متن فارسی نمونه را وارد یا انتخاب کند.
5. عملیات تحلیل هوشمند را اجرا کند.
6. پیشنهادهای اصلاحی نمونه را مشاهده کند.
7. بعضی پیشنهادها را تأیید یا رد کند.
8. نسخه اصلاح‌شده و یک پیش‌نمایش ساده از صفحه کتاب را مشاهده کند.

## اصل محوری فاز اول

مسیر اصلی دمو باید حتی بدون اتصال به مدل هوش مصنوعی خارجی قابل اجرا باشد. در صورت آماده‌نبودن مدل، Backend باید از پاسخ Mock یا Rule-based استفاده کند.

## ساختار فنی

پروژه به‌صورت Monorepo نگه‌داری می‌شود:

- `apps/frontend`: رابط کاربری React + TypeScript + Vite
- `apps/backend`: Backend مبتنی بر Django و Django REST Framework
- `docs`: معماری، استانداردها، قراردادهای API و نقشه راه
- `.github`: قالب‌های Pull Request و تنظیمات همکاری تیم

## قواعد همکاری

- توسعه مستقیم روی `main` ممنوع است.
- هر Task باید Branch مستقل داشته باشد.
- ورود کد به `main` فقط از طریق Pull Request انجام می‌شود.
- هر Pull Request حداقل به یک Review نیاز دارد.
- قرارداد API باید پیش از اتصال Frontend و Backend مکتوب شود.
- فایل‌های محرمانه، `.env`، دیتابیس محلی و Dependencyهای نصب‌شده وارد Git نمی‌شوند.
- کد تولیدشده با ابزارهای هوش مصنوعی بدون Review انسانی Merge نمی‌شود.
